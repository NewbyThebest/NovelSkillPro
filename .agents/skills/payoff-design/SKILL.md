# 爽点设计

解决“糖怎么选、怎么配、给够没给够”。桥段是具体场景，不是抽象机制；调用时保住每条桥段的独特性，不要用上位概念把它抹平。

## 边界

- 本技能管：本段该给哪几种爽点、这类爽点在本书的什么场合成立、和前文重没重复、连用会不会腻。
- 不管压迫怎么来、怎么升级、怎么还回去——那是 `conflict-design` 的冲突七型与兑现七型。
- 不管打斗场内的动作质感与招式爽感——那是 `combat-writing`。
- 不管题材调性与读者预期——那是 `genre`。
- 不管卡文时整段路线怎么走——那是 `webnovel-plot-navigation`。

三者是交叉关系，不是替代关系：`conflict-design` 定“为什么爽”，本技能定“爽的是哪一款”，`combat-writing` 定“这一招怎么打出去才爽”。同一场景可以三层同时用。

## 三层区分

| 层 | 回答什么 | 粒度 | 在哪 |
|---|---|---|---|
| **桥段层** | 读者看到的这件事长什么样 | 一个具体场景 | `references/爽点桥段库.md` |
| **机制层** | 凭什么这件事会爽 | 抽象归类 | `conflict-design` 兑现七型 |
| **节奏层** | 这段现在该不该给糖 | 蓄势／兑现 | `conflict-design` 结算节奏 |

桥段决定了这一场写什么，机制决定了它成立不成立，节奏决定了什么时候给。先定桥段再验证机制，不要反过来先用“实力揭露”套题材，那会写出所有书都一样的东西。

## 检索

### 入口一：从读者欠的情绪反查

先问本轮读者欠什么，再去索引按爽感列筛：

- 被压久了欠出气 → 打脸、借势、权威认错
- 一直被当废物欠证明 → 能力确认、弱势配置反杀
- 和主角的信息差已经拉开 → 身份揭露、知情者旁观、全局看戏
- 长期没拿到实际好处 → 资源暴富、机缘、变废为宝
- 关系没着落 → 归属、护短、被无条件信任
- 局面被别人牵着走 → 布局反制、立规、顺水推舟

### 入口二：从当前局面能承载什么反查

先盘点这一场现成的条件，再按前置成本筛。桥段调不出来，多数时候不是想不到，是**前置没铺**：

- 手上有谁是“将信将疑的旁观者”？→ 可走权威认错、见识势力
- 有没有一个已经立过威的强敌？→ 可走戏耍绝杀、弱势反杀
- 有没有已经写过“无用”的东西？→ 可走变废为宝、冷门杂学破局
- 有没有埋过没揭的身份或传闻？→ 可走神秘高人、傀儡掌权
- 有没有欠过人情的人？→ 可走厚报、顺水结缘

先读 `references/爽点索引.md` 定位候选，再读 `references/爽点桥段库.md` 的对应条目取完整字段。不要通读全库。

### 库内条目的回报类型不一

库内混有压力、伏笔、燃点、钩子、人物弧光等非爽点功能的条目。调用时按“当前缺哪种情绪”取用，不要因为编号在库里就当成糖往上堆——压力条目给多了会变成纯虐，伏笔条目给多了会变成不结算。

## 落地

选中桥段后，按这四问把它变成能让读者记住的那种写法，四问缺一项桥段就会塌：

1. **谁在误判**：不止“有人看不起主角”，要点出具体的人、他基于什么信息得出的判断。
2. **误判依据合不合理**：对手不能明知真相还硬送脸。让他的错误判断站得住，反转才成立。
3. **兑现场合够不够重**：同一个桥段放在私下和放在当众，爽感差一个量级。关键人物在不在场、赌注压没压上。
4. **结算落到谁身上**：谁改变了对主角的判断、谁付了代价、主角实际拿到了什么。没有第四项的桥段等于没写。

### 变量法

同一桥段的差异全部来自换这四项，换一项就是另一个场景，不算重复：

- 换误判者（小喽啰／同辈／权威前辈／整个行业）
- 换误判依据（看错实力／看错身份／看错物品价值／看错关系）
- 换兑现场合（私下／门派内／多方在场／公开场合）
- 换结算对象（当事人／旁观者／背后的势力）

## 配比与重复

### 连用纪律

- 同一桥段连续使用不超过两次，第三次读者已经预判到结果，爽点归零。
- 同一条连用风险高的桥段，两章之内不要重复；连用风险低的可以反复，但每次必须换误判者和兑现场合。
- 一卷之内不要让相邻的两个爽点来自同一爽感类型，中间插一个不同情绪（压力、关系、信息）。

### 蓄势与兑现的配比

- 蓄势段不要硬塞大爽点，会打断节奏；但可以放低连用风险的姿态类、细节类桥段维持手感。
- 兑现段不要只给一种，主桥段＋一个反向补刀（如先打脸再立规）比单点更实。
- 长线桥段（傀儡掌权、敌人底牌出自主角、立规）前期每一次露头都要让人觉得“有东西在动”，不能只在揭晓那一章才出现。

## 诊断模式

用户拿了已有片段或章纲来问，先判断问题类型，再给方案：

| 症状 | 判断 | 处理 |
|---|---|---|
| **不爽** | 桥段本身选对了，但四问缺了第三、四项 | 补兑现场合与结算对象 |
| **写软** | 反击靠讲道理、靠对方良心发现、靠苦熬 | 换成主角的牌落地，见 `conflict-design` 兑现七型 |
| **没爽点** | 整段只有推进，没有任何情绪回报 | 从索引按“读者欠什么”补一个桥段 |
| **重复** | 近期用过同一条或同爽感类型 | 换误判者与兑现场合，或换爽感类型 |
| **腻了** | 桥段对但太密，读者已无落差 | 抽掉一次，中间插压力或关系段 |
| **空转** | 桥段写出来了，但没改变任何人的判断 | 补结算对象，或换一个真正有代价的场合 |

区分蓄势段和兑现段再判断：蓄势段没当场爽点不是问题，缺的是后续兑现预期和主角动作。

## 输出格式

```markdown
## 爽点设计

### 1. 当前诊断
- **本段位置**：蓄势 / 兑现 / 常驻
- **读者当前欠的情绪**：
- **近期已用桥段与爽感类型**：
- **本次要避开的重复**：

### 2. 选型
- **主桥段**：[编号 + 名称]，爽感：[类型]
- **选用理由**：本书现有什么条件承载它
- **前置缺口**：[缺什么要补，缺得多就换一条]

### 3. 落地四问
- **谁在误判**：
- **误判依据**：
- **兑现场合**：谁在场，赌注是什么
- **结算对象**：谁改变判断，主角拿到什么

### 4. 补刀与配比
- **反向补刀**：[第二条桥段，没有则写无]
- **后续兑现预期**：[长线桥段才有]

### 5. 写崩风险
[这条桥段最容易被写坏的地方，以及本段的规避方式]
```

用户要求示范时，给 300—600 字片段，用事件、动作、对话推进。不做桥段说明、不复述库内条目原文。

## 自查

- [ ] 选的是具体桥段，不是先套抽象机制再往下编？
- [ ] 落地四问是否四项齐全，尤其结算对象？
- [ ] 误判者的判断是否站得住，不是明知真相硬送脸？
- [ ] 和最近三到五章用过的是不是同一条或同一爽感类型？
- [ ] 这一段是蓄势还是兑现，配比对不对？
- [ ] 加进去之后，局面或某人的判断是否真的变了？
