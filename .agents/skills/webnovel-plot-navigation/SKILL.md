# 网文剧情导航

先锁定需要解决的章节规模，再判断当前故事链缺了哪一环。场景与套路只用于生成路线，不能用一个动作点代替一整章，也不能由全书规划反推近期任务。

## 边界

- 只做卡点诊断和 3—5 条候选路线，每条按确认范围给出逐章章纲式思路；不写正文，不修改或覆盖正式小说文件。
- 适用范围为下一章、后续几章或一个小单元。用户提到“下一场”时，也先确认该场景所属章节与本轮覆盖范围；场景只作为章内素材，不作为正式候选。阶段、篇章或全书规划不在本技能内。
- 章数决定内容容量，推进上限决定最终写到哪里，两者必须分别确认。
- 不把候选说成已确认剧情，不替作者选首选。作者选中、组合或否定后再深化。

## 步骤 1：确认章节规模

先确定具体章号、起止范围或章数。用户已经明确“第 45 章”“后续三章”“第 45—47 章”等范围时直接采用；只说“后面怎么写”“给几个方向”而没有范围时，先询问需要几章或哪几章，得到回答后再读取项目材料和生成候选。用户要求代定时，先选定并说明一个具体范围。

完整章节默认按项目现有正文的通常篇幅设计；项目没有篇幅标准时，按一章能够独立承载一个完整叙事功能处理。章数一经确认，所有候选都必须覆盖这些章节。

## 步骤 2：读取材料

优先使用用户本轮提供的想法、限制和预期。用户指定小说项目时，按需读取：

1. 最近三至五章正文，至少完整读取上一章结尾。
2. 最新进度、角色状态与伏笔记录。
3. 当前小单元或近期章纲。
4. 本轮涉及的角色、关系、世界规则与核心机制。
5. 作品预期和全书总纲，只用于最后的相容性检查。

不要因为文件存在就读取全书正文。

按材料完整度分两档：

- **完整导航**：有上一结果、在场人物、当前目标和基本限制，可以完成事实挂接与完整筛选。
- **有限导航**：只有片段、梗概或一个场景问题。仍可生成结构思路，但缺少的人物、规则、关系或长线前置必须标为“待挂接”，不能擅自补成事实；只有一个缺项会改变全部路线时才追问。有限只表示材料不完整，不降低章节覆盖、逐章结构和内容容量要求。

区分：

- **定稿事实**：正文已经发生，任何候选都不能改写。
- **作者已定真相**：设定或规划已经确认，但人物与读者未必知道。
- **路线假设**：只在某条候选中成立，必须交给作者确认。
- **待挂接槽位**：有限导航中尚无作品事实承载的结构位置，例如“一个会因结果受损的既有角色”；它不是新设定，作者未确认前不能进入正式路线。

## 步骤 3：确认推进预算

从材料中找出会实质改变候选路线的推进节点。定稿事实只决定从哪里开始；章纲、进度或总纲中的下一步属于既有规划，除非用户明确要求沿用，否则不能替作者决定本轮写到哪里。

用户尚未说明这些节点写到什么程度时，先概括故事起点，再列出二至四个由浅到深的结果层级，询问整个章节范围结束时希望到哪一级。若既有章纲已有安排，说明它对应哪一级。选项只描述结果与幅度，不预设具体走法。得到回答后再生成候选。

据此确定窗口中心、明确停点、关注点与冻结项，并判断任务结果、信息、资源与处境、情绪、关系、能力、身份、地图和主线阶段分别允许多大变化。变化预算必须注明作用对象，不能借一条轴获得授权后顺带推进其他对象或节点。

只有作者明确表示不确定、没有偏好或要求代为决定时，才采用保守推进：整个窗口只完成一个中心变化，不改变核心身份、地图、阶段、关系定性或能力层级。

## 步骤 4：建立当前故事状态

先提取，不急着给点子：

- **上一结果**：最近一个行动、选择或揭示实际改变了什么。
- **人物状态**：在场关键人物各自想得到、保住、隐藏与避免什么；知道什么，不知道什么；能做什么。
- **迫近问题**：不处理就无法自然继续的危险、请求、决定、承诺或现场状态。
- **局部欠账**：近期已经铺垫、适合获得小回报的胜负、信息、关系、能力或后果。
- **可用条件**：已有场景、规则、资源、身份差、信息差与人物关系。
- **近期重复**：最近三至五章反复使用的场景、阻力、转折、结果与情绪。

事实与判断分开。作者已定真相不能变成人物提前知道的信息。

## 步骤 5：诊断缺环与分配章节功能

完整读取 `references/思路检索法.md`。

1. 用以下因果链找出最先断开的环节：

`上一结果 → 反应 → 困境 → 决定 → 场景目标 → 阻力 → 转折 → 选择／行动 → 结果 → 新状态`

2. 缺环只用于确定第一章如何承接，不能直接当作整个窗口的内容。根据已确认章数，把窗口中心拆成逐章功能：每章完成一个清楚的主功能，并由上一章结果自然产生下一章目标。
3. 只有一章时，围绕同一个中心冲突形成完整章内弧线；多章时，形成“建立目标—尝试受阻—调整选择—局部结果”的跨章弧线，不能把一章的内容摊薄成多章，也不能让某一章只负责赶路、说明或等待。
4. 行动场刚结束时，先补必要的反应、困境与决定；人物暂时没有目标时，从上一结果、人物欲望、他人独立行动和当前环境中寻找小目标，不能直接搬运长线终点。

## 步骤 6：检索并组合

按以下顺序检索：

1. 先把变化预算转成检索黑名单，排除未经授权的身份、能力、关系、地图和阶段变化。
2. 完整读取 `references/套路索引.md`，按缺环、逐章功能、冲突来源与预期结果选出候选编号，再到 `references/套路池.md` 读取其完整前置、骨架和失效条件。
3. 完整读取 `references/场景原型库.md` 与 `references/变化机制库.md`，为路线选择不同的场景载体、主要阻力和必要的改向机制。
4. 确定核心题材时，读取 `references/题材转换.md` 的对应条目。
5. 覆盖两章以上或一个小单元时，完整读取 `references/中程路线池.md`；模块必须逐项通过变化预算，不能反向扩大章数或推进尺度。

用以下公式生成场景素材：

`已有事实触发 + 有利益的人行动 + 场景目标 + 场景载体 + 主要阻力 + 人物选择 + 可见结果`

场景素材只用于搭建路线，不能直接作为整章候选输出。材料充分时先发散 6—8 条路线毛坯，尽量更换行动发起者、策略、阻力、转折和结果；有限导航只使用已有事实能够承载的要素，不为凑数新增人物、规则、资源、期限或幕后答案。

## 步骤 7：展开逐章内容并校验容量

每条路线先确定窗口中心和最终停点，再按已确认范围逐章展开。每章沿用项目章纲的五项结构：

1. **本章功能与目标**：本章独立承担什么叙事功能，人物具体争取什么。
2. **剧情骨架**：每章列出 5—8 个可直接扩写的连续节点，覆盖承接、行动或互动、阻力与反应、策略调整或人物选择、可见结果和章尾落点。节点必须产生新动作、新信息、新反应或新处境，不能把一个动作拆成若干微小步骤凑数。
3. **读者回报或压力**：本章兑现什么，并留下什么未解决的压力。
4. **伏笔与线索**：只记录本章实际使用、推进或新增的线索；没有则写“无”，不强行埋设。
5. **结尾状态**：准确说明人物、目标与现场状态发生了什么变化，以及下一章从哪里接。

推进上限只规定窗口最终停在哪里，不限制到达停点前可以发生多少轮有意义的尝试、误判、受阻、反应和调整。一个中心变化不等于一个场景动作。

多章路线中，每章都要有独立功能、可见变化和章尾状态，前章结果必须自然触发后章目标。不能把本可一章写完的内容摊薄，也不能用回顾、赶路、说明、等待或同一冲突反复重演占满一章。

若确认的章数与推进上限无法同时提供足量内容，停止生成候选，说明容量冲突，并请作者缩短范围或放宽停点；不得注水硬撑。

## 步骤 8：筛选候选

每条候选必须满足：

- 覆盖作者确认的全部章节，每章内容量足以支撑项目通常篇幅。
- 直接接住当前故事状态，逐章因果连续，每章都有独立功能、具体阻力、人物选择、可见变化和章尾状态。
- 不超过作者确认的推进预算，不触碰冻结项。
- 完整导航至少使用一个本书已有的专属条件改变通用套路；有限导航缺少承载事实的结构只能标为待挂接。
- 不靠角色降智、偶然救场或此前毫无依据的关键答案，不把同一动作或同一冲突拆散注水。
- 窗口结束后仍保留目标、压力与选择空间，不顺手结算多条线。
- 与其他候选至少在行动发起者、核心策略、主要阻力、转折机制、逐章结果或最终停点中有两项不同。

完整导航候选不足三条时，先更换路线结构，不能通过扩大尺度、新增设定或降低每章容量凑数。有限导航不足三条时可以少给，并说明缺少哪类可挂接事实。

## 步骤 9：长线后置校验

完整读取 `references/长线校准.md`。项目存在预期与总纲时再读取相关部分；用户只提供片段或梗概时，以其明确限制和已知事实完成有限校验，不因缺少全书规划阻塞导航。

- 只淘汰与定稿事实、底层规则、作者冻结项或明确未来顺序冲突的候选。
- 只修正提前透支成长、真相、关系和篇章节点的候选。
- “本轮没有推进长线”不是问题，不能为了证明有用而给局部路线强加权限、身份、通路、升级或阶段资产。
- 阶段完成条件看似达到，也不能自行宣布收束或切换阶段。

## 输出

不要展示套路编号和内部组合过程。每条候选必须覆盖确认的全部章节，并按项目现有章纲结构输出：

```markdown
## 剧情导航

### 当前诊断
- **覆盖章节**：
- **窗口推进上限与明确停点**：
- **当前故事状态与首个缺环**：
- **近期应避开的重复与抢跑**：

### 路线一：[体现核心策略或局部变化的名字]
- **路线中心**：[这几章围绕什么冲突或任务展开]
- **章节分配**：[每章各承担什么功能，为什么需要这些章]

#### 第 X 章 · [暂定标题或功能名]

**本章功能与目标**

[本章独立功能、人物目标及承接关系]

**剧情骨架**

1. [承接与即时动作]
2. [第一轮推进或互动]
3. [阻力与人物反应]
4. [策略调整、选择或关系交锋]
5. [进一步推进与可见结果]
6. [章尾落点]

**读者回报或压力**

[本章兑现的回报与留下的压力]

**伏笔与线索**

[实际使用、推进或新增的线索；没有则写“无”]

**结尾状态**

[本章结束后人物、目标和现场的准确状态]

[在同一路线内，把覆盖范围中的每一章完整展开为以上五项，不得用“同上”或概述代替]

- **路线假设、待挂接或风险**：无 / [需要作者确认的答案] / [缺少哪项作品事实承载]

[输出其余 2—4 条完整路线；每条都不得省略任一章]

### 横向区别
| 路线 | 核心策略 | 逐章推进差异 | 窗口最终结果 | 主要风险 |
```

候选默认并列。只有用户明确询问“哪条最好”时才比较推荐；不因输出较长而省略任一章的内容。

## 自查

- 是否先确认了具体章号或章数，再读取材料和确认推进上限？
- 每条路线是否覆盖全部指定章节，并逐章给出五项结构？
- 每章是否有独立功能、5—8 个有效剧情节点、可见变化和明确结尾状态，足以支撑项目通常篇幅？
- 是否没有把一个动作拆细、把同一冲突重复或用说明、赶路、等待注水？
- 是否准确定位首个缺环，并让后续各章由前章结果自然触发？
- 候选是否在核心策略、阻力、转折或逐章结果上真正不同？
- 是否没有把既有规划当成作者本轮决定，也没有借长线校验扩大近期任务？
- 是否没有修改小说文件或续写正文？
