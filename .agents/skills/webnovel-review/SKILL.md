# 正文审查

对一份正文草稿做独立审查，输出报告交回写作会话汇总转达。

审查方**全程只读**：不改写正文、设定、大纲或控制台，不代替作者决定剧情。

**汇总会话只整理与转达，不处置。** 三份报告返回后，写作会话只把它们汇总成报告交给用户，**不得动正文**；每条问题的处理办法由用户决定，用户发话之前不动手。

## 审查对象

只有一处：待审正文草稿 `4-正文/第X章_草稿_[标题].md`。规范指定的材料都围绕这一处核对，不审查其他章节、不审查全局资料。

## 执行

审查**一轮完成，不做复审**：报告交付后本次审查即结束，写作会话修正后不再发回审查方。

审查的独立性由下面的三个子代理承载，**无论谁调用本技能都照此执行**。**严禁在当前会话内自审，也严禁假扮审查方**——写完本章的会话会沿用自己写作时的判断，把问题读成理所当然。宿主不支持拉起子代理时，告知用户本技能不可执行并停止，不得跳过隔离直接审查。

1. **确认对象**：确定待审草稿的路径与本章章号。同一章存在多份草稿时，向用户确认审哪一份。

2. **三册并行**：**同时拉起三个独立子代理**，每个只读共用规范与自己的分册，只审自己那部分：

   | 子代理 | 规范 | 负责 |
   | :--- | :--- | :--- |
   | 甲 | `references/审查规范_共用.md` + `references/审查规范_正文与章纲.md` | 产出格式、脚本校准、可读性、创作原料落实、项目文本规则 |
   | 乙 | `references/审查规范_共用.md` + `references/审查规范_控制台.md` | 时间线、地图、角色状态、主角能力与资源四项对账，以及关键结果的可推导性 |
   | 丙 | `references/审查规范_共用.md` + `references/审查规范_设定.md` | 设定一致性、核心机制、设定待补全 |

   三个子代理各自输出一份报告，互不参照。**三份报告都没有问题才算通过**；任一份报出问题即按第 4 条汇总转达。

   **任务书只给四样**：自己那两册规范的路径、待审草稿路径、本章章纲条目位置、自己的分工代号（甲／乙／丙），外加为畅通执行所必需的路径与工作目录信息。**不要另列依据材料清单**——读哪些材料由分册规定；**不要把它不负责的维度、判定纪律或任何结论性提示复述给它**。送审后发现往任务书里夹带了清单、跨册维度或判断提示，本轮审查作废，把任务书改干净后重新送审。

3. **冻结**：送审后停止一切写入，等本轮审查结论返回；报告返回后同样不改动正文。

4. **汇总转达**：把三份报告逐条整理进下面那份报告，写明问题与依据，**原样交给用户**。报告提的是**问题与依据**，采信它指出的事实，不必另行验算。
   - **一律不动正文**：不修、不改、不代为拍板，也不替它算改法。
   - **问题**：列为待处置，写明依据与位置。
   - **建议**：原样记录，说明未修改。
   - **无法判定**：记录并说明缺什么材料。
   - **处理权在用户**：用户看过报告、发出指示之后，才轮得到动手。

5. **输出报告**：汇总三份报告，逐条列出待处置项，交给用户。

```markdown
## 正文审查报告 · 第 X 章

草稿：[文件路径]
审查结论：[三份报告均无问题 / 有问题待修复]
标点与引号校准：[读取校准脚本的汇总行，写「本章标点与引号共修复 N 处」或「本章标点与引号无需修复」，并列出仍无法自动判定的引号位置（如有）]

### 审查核对表

| 检查项 | 判定 | 说明 |
| :--- | :--- | :--- |
| **1. 产出格式** | | |
| 文件名与标题 | | 是否为 `第X章_草稿_[标题].md`，标题是否与本章章纲一致 |
| 正文开头 | | 是否从第一句正文开始，不含 `# 第X章`、章节名或其他标题行 |
| 草稿唯一性 | | 同一章是否只保留一份草稿，无重复或旧版本并存 |
| **2. 脚本校准复核** | | |
| 句号换行 | | 交付前是否已运行句号换行校准 |
| 标点与引号 | | 交付前是否已运行标点与引号校准；填写修复 N 处 |
| 字数 | XX 字 | 与参考区间的关系 |
| **3. 创作原料落实** | | |
| 原料逐条落实 | | 章纲无「创作原料」节时标不适用；有该节时只列遗漏条目（附原料原文与正文位置） |
| **4. 事实边界与连续性** | | |
| 时间 | | 时间词、跨日顺序、期限、倒计时能否挂接已有时间锚点 |
| 空间 | | 地点能否挂接已确认地点，或已明确标为本章新发现 |
| 角色状态 | | 处境、身体与精神、在场人物、伤势、认知边界是否与前文一致 |
| 能力与资源 | | 能力可调用性与效果限制；资源按获得、消耗、归还、转移、遗失对账 |
| 结果可推导性 | | 改变局面的结果能否由人物行动、已知规则或前置线索推出 |
| 核心机制 | | 是否符合 `2-设定/2.2_金手指设定.md` 的规则、代价与限制 |
| **5. 项目文本规则** | | |
| AGENTS.md | | 按项目根目录 `AGENTS.md` 最新内容逐条核对 |
| **6. 可读性** | | |
| 读者能否理解 | | 是否存在信息缺失或表述导致读者读完该处后无法确定发生了什么 |

### 待处置的问题（未修改，交用户决定）
- [问题] → [依据与位置；无则写“无”]

### 建议（未修改，供作者参考）
- [建议内容；无则写“无”]

### 无法判定
- [缺材料的项目；无则写“无”]
```

判定取值：一般项为 `通过`、`待处置`、`不适用`；脚本项为 `已执行`、`未执行`。章纲无“创作原料”节时，该项标 `不适用`。

## 单独使用

对已有草稿单独执行时，流程相同，从第 2 步开始。审完把报告交给用户，由用户决定是否修改。
