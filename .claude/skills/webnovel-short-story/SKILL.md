# 番茄短故事创作

## 目标与路径

把一个核心矛盾发展为可在 10-20 章内完成承诺、反转和结算的短故事。用户指定章节数或单章字数时优先；默认单章 800-1500 字。

- 将本技能目录记为 `SKILL_DIR`，包含 `.agents/` 的项目根目录记为 `WORKSPACE_ROOT`。
- 所有短篇正文调用均显式使用 `SHORT_STORY_MODE`：短篇方向大纲与短篇章纲代替长篇总纲和十章章纲。
- 番茄短故事按发布形态是单篇整文，不分章节。本项目写作期仍拆成单章独立写作与迭代，全部定稿后再合并成一份整文；导语独立于所有章节之外，不并入任何一章正文。
- `控制台/时间线.md` 是短篇同样必需的时间事实账；已有时先读取当前锚点、期限和不确定项，不存在时在首次定稿前建立。
- `控制台/地图.md` 是短篇同样必需的空间事实账，首次定稿时建立；没有需要跨章复用的空间事实时保留模板并写“无已定稿项目”，有转场、追逐、搜索、封闭空间或路线限制时才登记稳定地点、连通关系和限制，不把短篇扩写成完整世界地图。
- 已有 `控制台/进度.md` 时先读取进度、近期情节流、待办和活动线索，再继续未完成章节；不存在时从初始化开始。

## 短篇共用口径

- 导语和第一章要快速给出具体事件、压力、异常、关系问题或反差，不慢铺背景。
- 导语独立于所有章节，不写进任何一章正文；章节正文从本节第一句剧情开始，不重复导语内容。
- 每章必须完成至少一种有效变化：推进事件、改变关系、揭露信息、累积压力、兑现回报或完成结算。收束章可留余波，不强行钩下一章。
- 反转、反击、真相或关系变化应由已给出的证据、选择和人物利益推动；不按固定章数硬塞反转。
- 短篇偏重情绪与关系，但悬疑、职场、求生、成长或其他驱动同样可成立。世界规则只写会改变选择的部分。

## 执行顺序

### 第 0 步：初始化

逐项创建缺失目录：`1-预期`、`2-设定`、`3-大纲`、`4-正文`、`控制台`。已有文件不覆盖。首次定稿前按 `<WORKSPACE_ROOT>/.agents/skills/webnovel-dinggao/references/时间线模板.md` 创建 `控制台/时间线.md`，只填写已经发生的短篇时间事实；首次定稿前按 `<WORKSPACE_ROOT>/.agents/skills/webnovel-dinggao/references/地图模板.md` 创建 `控制台/地图.md`，只填写已经发生且可复用的空间事实；没有空间变化时保留模板中的“无已定稿项目”。

### 第 1 步：创作预期

读取并执行 `webnovel-expectation`。明确短篇篇幅、核心矛盾、读者情绪和结算方向，写入 `1-预期/1.1_预期.md`。

### 第 2 步：必要设定

读取并执行 `webnovel-ideation`，但按短篇实际需要控制设定规模：只建立支撑核心冲突、人物选择和结算的规则、角色和文风，不把短篇扩写成长篇世界观。

### 第 3 步：短篇方向大纲

完整读取 `<SKILL_DIR>/references/方向大纲.md`，基于预期和设定生成 `3-大纲/短篇方向大纲.md`。确认整体承诺、关键变化、结算和必要线索后继续；不提前批量生成逐章细纲。

### 第 4 步：标题

完整读取 `<SKILL_DIR>/references/标题.md`，生成或修订 `3-大纲/短篇标题.md`。用户确认主推标题后继续。

### 第 5 步：导语

完整读取 `<SKILL_DIR>/references/导语.md`，生成或修订 `4-正文/导语.md`。用户确认主推导语后继续。

导语属于正文，存放于 `4-正文/`，但**不并入任何一章正文文件**，等第 9 步合并时才放到成稿最前面。

导语写入后按章节正文同一标准跑强制校准（换行脚本必须显式传入导语路径，它不会自动扫目录）：

```bash
python "<WORKSPACE_ROOT>/.agents/skills/webnovel-zhengwen/scripts/check_sentence_linebreaks.py" --fix "<WORKSPACE_ROOT>/4-正文/导语.md"
python "<WORKSPACE_ROOT>/.agents/skills/webnovel-zhengwen/scripts/fix_quotes.py" --fix "<WORKSPACE_ROOT>/4-正文/导语.md"
```

### 第 6 步：逐章正文

读取并执行 `webnovel-zhengwen`，明确传入 `SHORT_STORY_MODE`。在该模式下：

- 读取 `3-大纲/短篇方向大纲.md` 和 `3-大纲/短篇章纲.md`，跳过长篇总纲和十章章纲。
- 逐章即时生成章纲并写入 `3-大纲/短篇章纲.md`，不批量锁死后续章节。
- 默认字数为 800-1500 字；每章只写本节剧情，**不带头部导语、不重复导语内容**。
- 仍遵循正文技能的事实边界、自查校准与交付分支；润色与审查由用户在选择时决定。

### 第 7 步：定稿回写

读取并执行 `webnovel-dinggao`，明确传入 `SHORT_STORY_MODE`。定稿后回写 `短篇章纲.md`，更新控制台；不因长篇十章范围自动触发规划修订。

### 第 8 步：完稿复核

最后一章定稿后，读取短篇方向大纲、全部定稿正文和控制台，检查：

1. 开篇承诺是否兑现，核心矛盾是否有可理解的结算。
2. 关键反转、证据和人物选择是否有前因，不靠临场新增信息。
3. 角色关系、状态和时间线是否前后一致。
4. 情绪走向是否完成预期，而非只堆压迫或只堆反转。
5. 导语、标题和正文实际内容是否仍相符，未误导读者；导语内容是否与第一章正文重复。
6. `控制台/时间线.md` 是否存在，事实截止是否与全部定稿一致；时间线不得引用未定稿章节。
7. `控制台/地图.md` 是否存在，事实截止是否与全部定稿一致；地图不得引用未定稿章节。故事出现跨章转场、追逐、搜索、封闭空间或路线限制时，稳定地点、连通关系和限制是否已登记；未确认的出口与路线不入账，等正文确认后再补。
8. `控制台/主角能力与资源.md` 是否存在，事实截止是否与全部定稿一致；动态总账不得提前计入未来变化。写明“当前无需要追踪的动态资产”时，正文和章纲是否确实没有需要跨章节核对的资产。

只报告实际问题和修改优先级；用户确认后再修改，不自动重写定稿正文。

### 第 9 步：合并成稿

全书章节全部定稿后，把分章草稿合并成番茄发布形态的单一成稿。执行：

```bash
python "<SKILL_DIR>/scripts/merge_short_story.py" --title "<书名>" --workdir "<WORKSPACE_ROOT>"
```

脚本按 `4-正文/` 下的 `第X章_定稿_[标题].md` 章序拼接，输出到 `4-正文/<书名>.md`。

成稿结构固定为：

```
导语正文
01
第一节正文
02
第二节正文
……
0N
第N节正文
```

- 导语取 `4-正文/导语.md` 的全部正文，**不写“导语”二字、不写标题行或其他标签**。
- 编号为两位阿拉伯数字（`01`、`02`……`10`、`11`），每个编号单独一行，编号后紧接该节正文。
- 各节正文之间不插入分隔线、章节标题或“全文完”之外的任何标记。
- 结尾追加一行 `全文完`。

合并前检查：`4-正文/` 下是否仍有 `_草稿_` 文件（存在即未全部定稿，停止并说明）；`第X章_定稿_` 是否存在缺号、重号或重复章节，有则停止并列出具体章号。

合并后报告成稿路径、总字数与章节数。已存在同名成稿时覆盖，覆盖前先说明原文件会被替换。
