# 文风润色

把已有正文的叙述声音改到 `2-设定/2.4_文风.md` 要求的样子。

由正文写作流程按用户选择调用，也可对任一已有正文单独执行。

## 承载方式

**必须由独立子代理承载，不在写作会话内自行润色。** 写作会话手里攥着章纲、设定、时间线和前文，写作时的判断会一路沿用，叙述声音正是被这些挤掉的那一项；它也最容易把改出来的声音读成理所当然。

- **由写作会话或用户直接调用时**：在写作会话之外拉起独立子代理，把本技能文件、待润色正文、`2-设定/2.4_文风.md`、本章章纲条目位置、本章出场角色档案路径交给它，由它读取本技能文件并执行。**任务书只给这些路径**，不写剧情摘要、改法提示或任何结论性说明；读什么、怎么改由本技能规定。夹带了就把任务书改干净重发。
- **已在独立子代理中运行时**：直接执行，不再向外拉起子代理，不嵌套。

宿主不支持拉起子代理时，告知用户本技能不可执行并停止，不得跳过隔离直接润色。

## 读取范围

只读这六类，**此外任何文件都不读**：

- 本技能文件
- `2-设定/2.4_文风.md`
- 该文件「语料来源」一节指明要读的语料
- **本章章纲条目**
- **本章出场角色的档案**：`2-设定/` 下的 `2.3_主要角色设定表.md`、`2.3.1_阶段与功能角色记录.md`，以及角色归档中对应角色的条目
- 待润色的那一份正文

除此以外不读任何文件，也不在项目里检索。

## 边界

**不能脱离本章章纲。**

## 执行

1. **读文风文档**。完整读 `2-设定/2.4_文风.md`，它是本次润色的唯一依据。

2. **读本章章纲条目**。长篇取当前十章章纲文件中的对应条目，短篇取 `3-大纲/短篇章纲.md` 中的对应条目。看清本章的剧情骨架、人物选择、结果、伏笔与结尾状态——这是本次改动的范围边界。

3. **读本章出场角色的档案**。取 `2-设定/2.3_主要角色设定表.md`、`2.3.1_阶段与功能角色记录.md` 及相关角色归档中对应本章出场角色的条目，看清各方的人设、说话方式与写作红线。

4. **取语料**。按文风文档「语料来源」一节写明的取法取料，读几章、怎么挑以那份文件为准。它列的两路都查。

5. **读正文**。完整读待润色的正文，先只读。

6. **逐段过一遍**。以**段落**为单位，把正文逐段拿到文风文档的判断项下过一遍，不是只找缺什么，而是逐段判它合不合要求：

   - 「本书要求」的每一条
   - 「总体」的四项：在讲的人、他知道多少、离人物多远、对人物的态度

   段落内部的问题（措辞、句式、视角落点）与**段落本身的问题（长短、节奏、该分该合、插话落在哪）一并判**。

   判完分三种处置：

   - **合要求的**：原样保留，一个字不动。
   - **不合要求的**：**改写这一段本身**——换句式、换措辞、调断句、并段或拆段、调视角落点。
   - **文风要求的成分整章缺席**：补写。文风文档要求哪些成分，就逐项核对哪些成分是否真的落在正文里；缺席的按文风文档的要求补上。

   **三者不是三选一，一章里往往都需要。** 改写解决句子和段落写得不对的地方，补写解决该有的成分根本没出现的地方；缺哪样做哪样，不得用一种代替另一种，也不得因为"已经改过了"就跳过补写。

   **除不能脱离章纲这一条外，一律放开手脚改。** 该补的补足，该重写的重写；不要因为"原文也能读"就手下留情。文风文档要求到什么程度，就改到什么程度。

7. **脚本校准（强制）**。改写后重跑一遍正文技能的脚本校准（`<正文技能目录>` 为 `.agents/skills/webnovel-zhengwen/` 的实际绝对路径）：

   ```bash
   python "<正文技能目录>/scripts/check_sentence_linebreaks.py" --fix "<正文路径>"
   python "<正文技能目录>/scripts/fix_quotes.py" --fix "<正文路径>"
   ```

8. **交付**：告知润色后的正文路径、字数变化，以及脚本校准的汇总行。发现与文风无关的问题一并说出来，交回写作会话处理。

## 写入范围

只写待润色的那一份正文文件，不写其他任何文件，不新建文件。
