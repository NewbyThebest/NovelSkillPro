# 正文审查规范 · 正文与章纲

配套文件：`审查规范_共用.md`（只读原则、处置分级、效率约束、报告结构）。本册是一套**按顺序执行的步骤**：一步只做一件事，做完一步就做下一步。

本册只读待审草稿、本章章纲条目和项目根 `AGENTS.md`，不读控制台与设定文件。

短篇模式下，`3-大纲/短篇方向大纲.md` 代替长篇总纲，第一章正文开头应含已确认的 `3-大纲/短篇导语.md`，字数参考改按短篇取值。

## 第 1 步 · 读草稿

读待审草稿 `4-正文/第X章_草稿_[标题].md`，通读一遍。

读完即进入第 2 步。

## 第 2 步 · 核产出格式

- 文件名是否为 `第X章_草稿_[标题].md`，标题是否与本章章纲一致。
- 正文是否从第一句正文开始，不含 `# 第X章`、章节名或其他标题行。
- 本章是否只保留一份草稿，没有并行草稿或旧版本混存。

核完即进入第 3 步。

## 第 3 步 · 跑脚本，核校准

正文交付前必须执行三个强制脚本。审查方用**诊断模式**复核其结果。**一律不加 `--fix`**。

在 `WORKSPACE_ROOT` 下执行（`<SKILL_DIR>` 为 `.agents/skills/webnovel-zhengwen/`）：

```bash
python "<SKILL_DIR>/scripts/check_sentence_linebreaks.py" "<草稿路径>"
python "<SKILL_DIR>/scripts/fix_quotes.py" "<草稿路径>"
python "<SKILL_DIR>/scripts/count_chinese_words.py" <章号> "4-正文" --min-chars <参考下限> --max-chars <参考上限>
```

- 句号换行：脚本报告仍有句号后继续书写的行时，指出具体位置。
- 标点与引号：脚本报告未配对或待人工确认的引号时，指出具体位置。
- 字数：长篇参考 `2000` 至 `4000`，短篇 `800` 至 `1500`，用户指定范围优先。低于区间时先判断是否缺少必要推进、结果或场景，不因字数本身判为问题。
- 字数脚本按章号自动选文件，同一章存在多个草稿时可能选中不是待审的那份：核对它输出的文件名与待审正文一致。不一致时该数字不可用，改用：

  ```bash
  python -c "import sys; sys.path.insert(0, '<SKILL_DIR>/scripts'); from pathlib import Path; import count_chinese_words as m; p=Path('<草稿路径>'); print(m.count_file(p), '字', p.name)"
  ```

核完即进入第 4 步。

## 第 4 步 · 核可读性

只审读得懂读不懂，不审文风、不提文风类修改要求。

- **判为问题的只有一种**：读者读完该处后，无法确定发生了什么。
- 读者能自行理解、只是需要多想一步或多读一遍的，不判为问题，也不列为建议。

核完即进入第 5 步。

## 第 5 步 · 读章纲条目，核创作原料落实

读本章章纲条目：长篇为当前十章章纲文件中的对应条目，短篇为 `3-大纲/短篇章纲.md` 中的对应条目。

**仅当本章章纲条目含「创作原料（定稿前临时保留）」节时才执行本节核对。** 没有该节时，本节直接跳过，下列要求不必读，报告里也不写这一节、不说明原因。

有该节时，逐条核对正文是否完整落实：

- **逐句核对**：把创作原料拆成可核对的最小条目（每个事件、人物选择、结果、对白意图、具体动作、场景细节和表达重点各算一条），逐条到正文中找落点。
- **位置可以变，意思不能变**：原料内容的先后顺序、出现位置、由谁叙述、放在哪个段落都可以调整；事件、人物选择、结果、对白意图、具体动作、场景细节和表达重点必须一致，不得删减、弱化、替换或改变含义。
- **分拆与合并允许**：原料中一条内容可在正文拆成多处，或多条合并到一处，只要内容不丢、意思不变。
- **措辞自由度**：正文用词、句式与原料不同不算遗漏；只有内容缺失或含义改变才算。
- **只列遗漏**：报告中只列遗漏条目，引用原料原文与正文对应位置（或指出正文中无对应内容）。遗漏属于必须修复的问题。
- 与章纲“剧情骨架”粒度不同不构成遗漏；原料与剧情骨架冲突时以原料为准。

核完即进入第 6 步。

## 第 6 步 · 读 `AGENTS.md`，核项目文本规则

**先看 `AGENTS.md` 有没有规则条目。** 没有时本步无命中：报告里不列本步、不写“不适用”、不解释原因，直接进入第 7 步。

有时读该文件，逐条核对正文。规则类别不固定，以它的最新内容为准；命中其中任一条的问题按实际影响定级。

核完即进入第 7 步。

## 第 7 步 · 写报告

按共用规范的报告结构输出报告。

报告只写**本册范围内**的发现：产出格式、脚本校准、可读性、创作原料、项目文本规则。

**到这一步审查结束。** 前六步记下的结论就是全部结论，不需要回头重看，也不需要再汇总核对一遍。审查方全程只读。
