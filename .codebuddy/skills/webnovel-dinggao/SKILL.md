# 定稿回写

## 目标与路径

用户确认章节定稿后，先确认最新正文与章纲的关系，再将这份正文作为后续维护的唯一事实来源。完成本章归档、控制台更新和必要的规划维护后，等待用户进入下一章，不自动继续写作。

- 将本技能目录记为 `SKILL_DIR`，包含 `.agents/` 的项目根目录记为 `WORKSPACE_ROOT`。
- 小说文件从 `WORKSPACE_ROOT` 读取和写入；模板从 `<SKILL_DIR>/references/` 的实际绝对路径读取。
- 已确认的定稿、控制台状态和已回写章纲不得被后续草稿覆盖。

## 步骤 0：定位章节与定稿前对齐

先执行控制台门槛：第一次章节定稿时必须创建 `控制台/时间线.md`、`控制台/地图.md` 与 `控制台/主角能力与资源.md`，以后每次定稿都必须读取并核对。文件缺失时，若项目已有定稿，先依据全部既有定稿重建，不能只从最新一章反推；若正在处理第一章定稿，则从本章定稿事实建立。时间线无法精确到日时保留相对时段和不确定项，不得自行补日期；地图无法确认的方向、出口、距离和区域关系保留在“未确认空间”，不得自行补成客观地图。没有持续动态资产时也不能省略总账，在“当前概况”写“当前无需要追踪的动态资产”，各事实分区写“无已定稿项目”。无法判断时继续核对正文事实，不得把不确定当作无资产或已确认空间。

1. 结合用户明确说明、当前对话、`4-正文/` 中的 `第X章_草稿_[标题].md` 或 `第X章_定稿_[标题].md`、以及 `控制台/进度.md` 定位待处理章节。
   - 上下文、文件和进度能指向同一章时继续。
   - 存在多个候选、章节号冲突或用户未说明时，停止并只问“要为第几章定稿？”。
2. 长篇模式按本章章号找到 `3-大纲/` 下对应的十章章纲文件。第 1—10 章使用 `章纲_1-10章.md`，第 11—20 章使用 `章纲_11-20章.md`，后续依此类推；文件名固定，不根据剧情目标或实际收束情况调整。`SHORT_STORY_MODE` 下读取 `3-大纲/短篇章纲.md`。读取其中本章章纲与待定稿正文。
3. 在重命名前做只读对齐：确认正文是否改变了本章核心事件、角色状态、伏笔、结尾状态或设定事实。
   - 无实质差异，或用户明确以当前正文为准时，继续转正。
   - 存在实质差异时，向用户列出“章纲 vs 正文”的事实差异，并让用户选择：按正文回写章纲，或先返回草稿修正。选择修稿时不转正、不更新控制台。
   - 本章存在“待定稿同步项”时，同时核对定稿正文是否实际保留了这些差异。已经没有进入正文的差异直接删除；仍然成立的差异留到步骤 4 处理，不在转正前擅自修改设定或总纲。
4. 本章涉及主要角色或核心关系时，读取 `2-设定/2.3_主要角色设定表.md` 或 `2-设定/2.3.2_核心关系.md` 的相关条目；出现、复用或结算阶段角色时，读取 `2-设定/2.3.1_阶段与功能角色记录.md` 的相关条目，判断正文产生的是短期状态还是稳定档案变化。当前文件的低频归档索引指向本章复用角色时，再读取对应 `2-设定/角色归档/[阶段名].md` 条目，不加载无关归档。
5. 读取 `控制台/时间线.md`，核对事实截止、当前时间锚点、相邻事件间隔、持续时长、期限与倒计时。本章正文出现“次日”“数日后”“第X日”、具体时辰或倒计时时，必须确认起点和跨度能被既有定稿支持；无法精确换算时保留原文相对时间并记入不确定项，不得补成绝对日序。
6. 读取 `控制台/地图.md`，核对本章涉及的区域、地点、已确认连通关系、局部方向、通行条件、监控或权限限制，以及本章移动是否把未确认空间写成既定事实。地图只保存跨章复用的空间结构；人物当前地点仍写入进度和角色状态，本章逐步走位仍以正文为准。
7. 读取 `控制台/主角能力与资源.md`，核对当前概况、事实截止和实际条目。第一章定稿时必须创建并从本章定稿事实填写；已有多章定稿但总账缺失时，必须先追溯全部定稿，重建截至最新章的当前动态资产。每次定稿都要核对总账，即使本章没有资产变化也不能跳过；本章首次出现需要跨章节核对的资产时，更新当前概况并纳入对应事实分区。
8. 用户确认以该正文定稿后，先执行中文标点与引号自动校准，再转正。这是**不得跳过的强制步骤**：无论是否认为正文标点和引号已正确，都必须实际运行脚本，不得凭判断省略或声称“已检查”。在 `WORKSPACE_ROOT` 下执行：

   ```bash
   python "<SKILL_DIR>/scripts/fix_quotes.py" --fix "<WORKSPACE_ROOT>/4-正文/第X章_草稿_[标题].md"
   ```

   将占位符替换为实际绝对路径和章节号。脚本按 `AGENTS.md` 统一修正英文半角句读、括号、破折号、省略号和错误引号，并交换左右写反的引号对；Markdown 代码、链接、网址、路径、小数与列表标记受保护。脚本报告修复后仍不配对的引号位置时，先说明并确认处理方式，再继续转正。随后将 `第X章_草稿_[标题].md` 重命名为 `第X章_定稿_[标题].md`，只替换状态字段并保留章节标题。标题在定稿前已经变更时，使用用户最新确认的安全文件名标题，不保留旧标题副本；用户已手动转正时直接使用定稿文件。正文内容从故事第一句开始，不在文件内重复章号或标题。
8. 若该章已经是定稿，且 `控制台/进度.md` 已记录为完成，默认视为已收尾，不重复更新。只有用户明确要求修复、补回写或重新结算时才继续。

## 步骤 1：回写本章章纲

以定稿正文为准更新本章章纲的事实描述：剧情骨架、读者回报或蓄势、伏笔线索和结尾状态。

- 回写剧情骨架时，定稿正文只用于确认已发生的事实，不按正文段落、动作链或场景镜头复述。
- 剧情骨架必须使用 Markdown 有序列表。每个列表项对应一次独立的局面变化，只写发生什么、谁作何选择、造成什么结果。
- 同一场连续行动中，若中途没有新的选择、信息或局面变化，应合并为同一项，不按动作先后拆成多项。
- 不回填具体台词、连续动作、招式过程、走位、现场反应、环境描写或情绪节拍，除非该细节本身改变后续剧情边界。
- 定稿正文与剧情骨架只需在事件顺序、人物选择、结果和已确认事实上一致。
- 只更新已被用户确认接受的正文差异，不反向改写定稿正文。
- 本章章纲缺失时，基于定稿正文补建最小可用记录，不补造未写出的剧情。
- 本章存在“创作原料（定稿前临时保留）”时，只有在正文转正且事实章纲回写完成后才删除该节。草稿生成、审查、润色或用户尚未确认定稿时不得提前清理。
- 没有写进定稿正文的创作原料默认不成为事实。用户明确要求留到后续时，先确认去向，再转入下一章创作原料或尚未写出的规划；不得自动写入控制台、角色档案或伏笔记录。
- “待定稿同步项”不随创作原料一起自动删除。只有对应差异未进入定稿正文，或已经按步骤 4 完成全局同步后，才清理对应条目；用户暂缓全局修订时保留该节。
- 回写完成后说明本章章纲是否有改动，以及改动的事实范围。

## 步骤 2：更新控制台

首次定稿时，若 `控制台/时间线.md`、`控制台/地图.md` 或 `控制台/主角能力与资源.md` 缺失，从 `<SKILL_DIR>/references/` 复制对应模板到 `控制台/`，删除模板提示后填写真实项目事实。时间线、地图与总账每个项目都必须存在。已有多章定稿但文件缺失时，先追溯全部定稿重建，不只记录本章变化；无法精确换算的时间必须保留不确定性，无法确认的空间关系必须放入地图的“未确认空间”。总账有动态资产时在“当前概况”概括资产类型，并登记当前事实；当前没有需要追踪的动态资产时，在“当前概况”写“当前无需要追踪的动态资产”，保留各分区并写“无已定稿项目”。

每次定稿后按以下规则更新：

| 文件 | 更新规则 |
| :--- | :--- |
| `控制台/时间线.md` | 每章必更：事实截止、当前时间锚点、本章造成的时间段推进、仍在运行的期限与倒计时、无法精确换算的时间边界。 |
| `控制台/进度.md` | 每章必更：当前承接、最近三章、最新定稿复盘、下一步与阶段缺口、压缩后的里程碑。 |
| `控制台/角色状态.md` | 按需更新当前活跃角色的即时动态快照；没有变化且仍属当前工作集时保留，不再影响当前阶段创作时删除。 |
| `控制台/主角能力与资源.md` | 每个项目必有；首次定稿创建，之后每章定稿都核对当前概况、事实截止和事实条目。资产发生变化时重建当前条目；没有动态资产时保留明确的无资产事实，不能因本章没有变化而跳过。 |
| `控制台/地图.md` | 每章核对；本章新增或确认跨章复用的区域、地点、连通关系、空间限制、方向、监控或权限事实时更新。只把定稿正文已确认的空间事实写入对应索引，猜测和未验证出口放入“未确认空间”；没有空间变化时保留原记录。 |
| `控制台/伏笔追踪.md` | 每章必审：新埋、推进、收回或失效的伏笔和关系线发生变化时更新。必须逐条对照待收回列表执行收回判定，不得只增不减。 |

所有记录只写正文已经发生的事实，不把下一章计划写成已发生状态，不把猜测写成伏笔结论或已确认空间。完成后明确列出本次实际更新的控制台文件和条目。

### 伏笔追踪与收回维护规则

`控制台/伏笔追踪.md` 是全书剧情悬念、暗线布局与未解之谜的动态追踪账，不是人物互动流水账或大纲副本。每章定稿时必须严格按以下规则维护：

1. **定稿伏笔逐章四问（强制过筛）**：
   每次定稿更新控制台时，必须对照“待收回伏笔”列表逐条自问：
   - ① **初始谜团是否已解**：本章剧情是否已经给出了该伏笔当初埋设时的核心答案（如：去向已查明、身份已揭晓、规则已验证）？
   - ② **是否达成阶段性闭环**：该事件的初始危机或任务是否已告一段落（如：买手锁定已完成签约、擂台增幅机制已实战摸清）？
   - ③ **是否已衍生为全新事件**：旧悬念是否已解决，并转化为新的明确目标（例如：“寻找方南枝去向”已查明，后续转为“如何营救方南枝”）？若已转化，旧条目必须收回，新目标按需另立条目。
   - ④ **是否仅为人物日常互动**：该条目是否只是两个角色之间的常规对话、情感升温或日常过招？若是，坚决移出伏笔表，归入下方的《关系发展线》维护。

2. **收回判定标准（区分“阶段答案”与“终极结局”）**：
   - 只要某个伏笔在正文中获得了**明确的事实印证或阶段性闭环**，哪怕其背后牵扯更大的长线主线，该条目也**必须立即判定为【已收回】**，移入“已收回伏笔”表格，并注明收回章节与结论。
   - 严禁以“人物还没逃出园区/还没彻底推翻反派”为由，将早已查明的阶段性谜团无限期堆积在“待收回”列表中。

3. **严格剥离人物关系流水账**：
   - 《待收回伏笔》表格**仅收录真正的谜团、阴谋、机制暗线与未决危机**。
   - 角色之间的信任建立、感情变化、日常斗嘴与默契推进，**统一由底部的《关系发展线》层级列表维护**，严禁在伏笔表格中逐章追加流水账。

4. **十章节点全量大盘点机制**：
   - 在第 10、20、30、40、50、60 章等固定十章审计节点，必须对《伏笔追踪表》进行全量体检：
     - 清理已在前文暗中收回或已失效的陈旧条目；
     - 检查是否有新埋伏笔被遗漏登记；
     - 确保“待收回”列表始终保持高度精炼、聚焦于当前及近端的核心悬念。

### 地图文件维护规则

`控制台/地图.md` 是唯一可跨章复用的空间事实账，不是人物位置表、逐章走位记录或完整世界百科。始终按 `<SKILL_DIR>/references/地图模板.md` 的结构维护：

1. **事实截止与区域边界**：每章定稿后更新到最新定稿章节；区域索引只收录已确认的区域层级与稳定功能，不补完整地图。
2. **地点与连通关系**：地点索引只收录会影响后续行动的稳定节点；连通关系必须标明行进参照、路程粒度和通行条件，不能把一次性走位扩成坐标或绝对方位。
3. **空间限制**：摄像头、权限门、衣着、门禁、地形和可见性等会改变后续选择的限制单列保存。
4. **未确认空间**：疑似出口、用途不明房间、未验证路线、角色推断和不完整方位放入“未确认空间”，后续确认后再转入已确认表。
5. **职责边界**：人物当前地点写入进度和角色状态；移动耗时写入时间线；本章具体走位留在正文与章纲；地图只保留稳定拓扑和限制。

每次定稿后运行：

```bash
python <SKILL_DIR>/scripts/validate_map.py <WORKSPACE_ROOT>
```

地图校验未通过时先修正地图再继续。脚本不可用时，至少人工确认：事实截止等于最新定稿；没有引用尚未定稿章节；区域、地点、连通关系和限制均有事实依据；未确认空间没有被写成确定地图；没有把人物动态位置和逐章走位复制进地图。

### 时间线文件维护规则

`控制台/时间线.md` 是唯一故事时间事实账，不是逐章剧情摘要。始终按 `<SKILL_DIR>/references/时间线模板.md` 的结构维护：

1. **事实截止与当前锚点**：每章定稿后更新到最新定稿章节，写清当前相对时段、当前事件所处时间位置和最近明确时长。无法确定绝对日期或入园第几天时必须直写“无法确认”。
2. **已定稿时间段**：按连续时间段合并章节，只记录会影响后续连续性的时点、时段、跨日、持续时长和事件先后；不得把逐章剧情复述搬入时间线。
3. **期限与规律**：单列仍在运行的倒计时、约定、治疗周期、固定时刻和巡查规律，写清起点、期限、当前状态与事实依据。期限结束、失效或完成时覆盖更新或移入已定稿时间段，不保留两份并行状态。
4. **不确定项**：正文只写“数日”“几日”“稍后”或存在包含关系时，保留原有粒度，说明不能推算什么；不得自行换算成固定天数，也不得把多个可能重叠的时段机械相加。
5. **时间冲突处理**：若本章时间词与旧定稿无法同时成立，先列出冲突并让用户确认，不静默改正文或旧时间线；用户明确以当前正文为准后，才按正文回写受影响的时间段和期限。
6. **职责边界**：时间线只管时间顺序、时长、时点、期限与不确定性。当前地点、章尾局面和下一步写入进度；角色即时状态写入角色状态；能力资源写入动态资产总账。

每次定稿后运行：

```bash
python <SKILL_DIR>/scripts/validate_timeline.py <WORKSPACE_ROOT>
```

校验未通过时先修正时间线再继续。脚本不可用时，至少人工确认：事实截止与当前章节等于最新定稿；时间段章节范围按顺序覆盖最新章；当前锚点四项齐全；没有引用尚未定稿章节；无法精确的时间没有被强行补全。

### 角色状态文件维护规则

`控制台/角色状态.md` 是下一章直接读取的动态工作表，不是已登场角色名册或逐章档案。始终按 `<SKILL_DIR>/references/角色状态模板.md` 的结构维护：

1. 只保留当前场景、下一章承接或当前阶段目标与约束仍需直接读取的角色。核心角色暂时离场，但其状态仍构成当前阶段目标或限制时，保留压缩快照。
2. 位置、即时伤势与精神状态、目标、认知和关系均覆盖更新，不在旧内容后追加章节经过。能力、资源或物品只写本章承接直接需要的即时状态，例如精神力刚耗损、正在维持伪装或某件物品此刻握在手中。
3. 主角完整能力与手段、来源与效果、融合关系、资源余额、关键物品、凭证和其他动态资产统一写入 `控制台/主角能力与资源.md`；角色状态不得复制完整清单或另建并行库存。总账当前写着“当前无需要追踪的动态资产”时，本章一旦出现需要跨章节核对的资产，就更新当前概况并补记当前事实。
4. 每个角色使用且只使用一个“最近更新依据”，只填写最后一次实际改变其状态的定稿章节；不得保留“本章变化依据”或列出多个历史章节。
5. 稳定身份、外貌、长期能力体系方向和人物写作边界写入角色设定；核心机制的长期规则写入金手指设定；长期未决问题写入伏笔追踪；逐章过程写入定稿正文和十章章纲，不在状态文件复制。
6. 角色死亡、永久离场、完成场景作用，或其状态已不影响当前阶段创作时，删除对应条目。可能复用的阶段角色由低频角色归档保存最后确认状态，重新进入当前规划时再补回状态条目。
7. 每章只处理本章发生变化或需要退出工作集的角色；第 10、20、30 章等十章节点和阶段切换时复查全部状态条目。

更新完成后运行：

```bash
python <SKILL_DIR>/scripts/validate_character_state.py <WORKSPACE_ROOT>
```

校验未通过时先修正角色状态文件再继续。脚本不可用时，至少人工确认：没有“本章变化依据”、每个角色恰有一个“最近更新依据”、该字段只含一个章节号、其他状态字段没有逐章历史、文件中没有已经退出当前工作集的角色。

### 主角动态资产总账维护规则

`控制台/主角能力与资源.md` 是每个项目首次定稿时必须建立的唯一主角动态事实总账。始终按 `<SKILL_DIR>/references/主角能力与资源模板.md` 的职责维护：

1. “当前概况”只用一句话概括正文已经成立的动态资产类型；当前没有动态资产时写“当前无需要追踪的动态资产”，并在各事实分区写“无已定稿项目”。以后首次出现需要跨章节核对的资产时，更新概况并补记事实。
2. 只记录当前结果，不按章节追加流水。稳定机制规则留在金手指设定，稳定人物资料留在主要角色设定表，即时位置、伤势、精神消耗、目标和关系压力留在角色状态。
3. 新获能力、能力改名、融合、失效、效果验证或限制变化时，覆盖对应能力条目；区分原始能力材料、重构后的能力和融合后的成型手段，别名与已并入能力不得重复计数。
4. 资源、关键物品、凭证和其他动态资产按“获得－消耗／归还／转移／失效＝当前持有”核对。正文未明确数量时写“数量未核定”“至少”或连续性依据，不能因近期没提便记为零；已经耗尽或不再持有的项目移入历史防误用区。
5. 每项能力或手段写清当前作用、限制和事实依据；资源写清余额、位置、用途限制和事实依据；关键物品、凭证与其他动态资产写清持有状态、权限与未决。
6. 未定稿章纲、创作原料和用户尚未落实到正文的未来奖励、消耗、突破或装备变化不得提前入账。事实截止必须更新为最新定稿章节，即使本章没有发生动态资产变化。

每次定稿后运行：

```bash
python <SKILL_DIR>/scripts/validate_protagonist_ledger.py <WORKSPACE_ROOT>
```

校验未通过时先修正再继续；脚本不可用时，至少人工确认：总账存在，当前概况与实际条目一致，事实截止等于最新定稿；当前余额与已耗尽区没有同一项目并行持有，总账没有未来计划或未定稿奖励，每项动态资产都有事实依据；写明无资产时，正文和章纲确实没有需要跨章节核对的动态资产。

### 进度文件维护规则

`控制台/进度.md` 是供下一章直接使用的动态工作台，不是逐章档案。始终按 `<SKILL_DIR>/references/进度模板.md` 的五段结构维护：

1. **当前承接**：记录当前章节、故事时间、地点、章尾局面和即时未决。无法确认具体时间、位置或身份时，写“具体未知”或“最后确认于”，不能把角色判断写成客观事实。
2. **近期情节流**：只保留最新三章定稿摘要，不足三章时保留已有全部。每章一至两句，只写影响下一章承接的选择、结果和状态变化；加入新章时删除最早一章，更早历史由对应十章章纲保存。
3. **最新定稿复盘**：只记录最新章的字数与状态、章纲差异、待同步项和定稿边界。没有差异或待同步项时直接写“无”，不累积历章复盘。
4. **下一步与阶段缺口**：长篇的当前阶段名称必须与总纲完全一致，`SHORT_STORY_MODE` 照录短篇方向中的当前推进段；下一章核心任务只写一个。近期行动保留一至三项，阶段完成缺口不超过三项，持续约束不用复选框。
5. **里程碑日志**：只记录不可逆状态变化、阶段结果、关键决策、核心能力链成形或全项目审计等跨章成果。不得写“第X章定稿”或逐章剧情复述；同一事件链合并成一条，通常保留五至十条。阶段结束时，将该阶段多条里程碑压缩为一条阶段结果。

每章定稿后立即删除已经完成的待办。确有跨章价值的完成项转为里程碑，其余直接删除。长期谜团与未收伏笔只在 `控制台/伏笔追踪.md` 维护，角色的伤势、位置、认知与关系只在 `控制台/角色状态.md` 维护，逐章历史只在十章章纲维护；进度文件不复制这些长记录。

更新完成后运行：

```bash
python <SKILL_DIR>/scripts/validate_progress.py <WORKSPACE_ROOT>
```

校验未通过时先修正进度文件再交付。脚本不可用时，至少人工确认：近期情节恰为最新三章、下一步没有 `[x]`、里程碑没有逐章定稿记录、当前章节与字数匹配最新定稿、当前阶段名称与对应的长篇总纲或短篇方向一致。

### 时间线强制校验

控制台回写完成后必须运行：

```bash
python <SKILL_DIR>/scripts/validate_timeline.py <WORKSPACE_ROOT>
```

时间线校验未通过时不得交付定稿。至少确认事实截止和当前章节等于最新定稿、当前时间锚点四项齐全、已定稿时间段按章节顺序覆盖最新章、期限与倒计时没有把未来计划写成已发生事实、无法精确换算的时间仍保留不确定性。

角色档案按以下规则处理：

- 当前位置、短期伤势、临时资源、即时关系状态和当章认知只写入控制台，不回写角色设定文件。
- 新出现的一次性人物在本章后仍会影响当前阶段或需要复用，并形成稳定外貌、能力、场景功能、最新结果或写作边界时，才补入 `2-设定/2.3.1_阶段与功能角色记录.md`。人物在同章完成全部作用且没有明确复用价值时不建档。
- 已有阶段角色出现不可逆结局或稳定设定变化时，覆盖更新其最新结果。“当前得失”和“当前场景结果”不得按章节追加经过，逐章历史只留在定稿正文和十章章纲。
- 不对应固定个人的岗位、群体和组织规则移入 `2-设定/2.1_新书设定案.md`，不继续作为角色条目维护。
- 阶段角色开始拥有独立长期目标、反复影响主线或形成持续关系时，将条目移入 `2-设定/2.3_主要角色设定表.md`，并从阶段角色文件删除旧条目，不保留两份版本。
- 阶段角色已经死亡、永久离场或完成全部作用，且没有明确复用价值时，从阶段角色文件删除。删除前确认其结果已经进入定稿正文和十章章纲，不另建完整历史档案。
- 角色确有复用可能、但当前阶段近期不再使用时，将稳定事实、最后确认状态、复用边界和事实来源移入 `2-设定/角色归档/[阶段名].md`，阶段角色文件只保留一行归档索引。角色重新进入当前规划时，将完整条目移回并删除归档旧条目。
- 每章只处理本章涉及的阶段角色；第 10、20、30 章等十章节点和阶段切换时复查阶段角色文件全部条目，逐一判断保留、升格、归入设定、删除或低频归档。
- 只有关系双方均已有 `2-设定/2.3_主要角色设定表.md` 中的角色条目，且已确认的核心关系基础或边界发生实质变化时，才更新 `2-设定/2.3.2_核心关系.md`。阶段与功能角色、归档角色和未建档人物不得在此建立条目；主要角色表中尚未形成核心关系的人物不补空白条目。尚未确认的未来关系只写入未写规划，不当成角色事实。

## 步骤 3：十章章纲范围（仅长篇）

长篇章纲按章节号固定为十章一个文件，不判断范围目标，不使用 `x`，也不因剧情实际收束而改名。

- 本章定稿后只回写其所属的十章章纲文件。
- 本章为第 10、20、30 章等范围末章时，文件保持原名和原有范围，不创建下一份章纲；但必须进入步骤 4 的十章节点全项目一致性审计。完成审计不等于必须修订规划。
- 下一章进入新的十章范围时，由 `webnovel-zhengwen` 创建对应的 `章纲_[起始章]-[结束章]章.md`，并写入新的“当前起点”。

短篇模式跳过本步骤。

## 步骤 4：一致性审计与按需规划修订

不在每章自动改总纲或设定。以下情况才触发复盘：

- 本章有仍然成立的“待定稿同步项”。
- 当前阶段的完成标志已经达成。
- 定稿正文持续偏离当前总纲的阶段方向、读者承诺或硬约束。
- 本章为第 10、20、30 章等固定十章节点。此时强制执行全项目一致性审计，但只有审计发现需要调整时才进入规划修订。
- 用户明确要求核对正文与预期、设定、大纲、控制台之间的出入。
- 用户明确要求调整后续规划。

### 十章节点全项目一致性审计

第 10、20、30 章等固定十章节点定稿后，必须同时执行事实一致性审计与剧情方向审计，不能只检查十章章纲。用户在非十章节点明确要求全面检查时也执行本节；用户未指定范围时，核对当前全部定稿正文。

#### 审计范围与事实源

1. 读取刚完成十章范围内的全部定稿正文，以正文中实际发生的内容作为事实源。当前文件引用了更早事实时，继续读取对应的早期定稿章节，不能凭控制台或记忆反推正文。
2. 读取当前项目中的全部 `1-预期/*.md`、`2-设定/*.md`、`3-大纲/*.md` 和 `控制台/*.md`，其中必须用 `控制台/时间线.md` 核对事件顺序、跨日、持续时长、期限和倒计时，用 `控制台/地图.md` 核对区域、地点、连通关系、局部方向、通行限制与未确认空间。若时间线或地图缺失、事实截止落后，先按定稿正文重建或补齐再继续审计。不读取旧流程备份、临时目录或技能镜像作为小说事实。
3. 草稿、创作原料和未来章纲只代表候选或计划，不能覆盖定稿正文。未写规划只检查起点、前提和因果是否仍然成立，不能当成已经发生。
4. `2.4_文风.md` 只核对其中「本书要求」是否仍被正文遵守，不在本步骤进行逐句文风审稿。

#### 事实一致性检查

逐项检查以下内容，不得只搜索同名关键词：

1. 人物身份、称呼、位置、伤势、能力、资源、认知、目标和关系是否与定稿正文一致。
2. 世界规则、组织权限、力量体系、核心机制的触发条件、能力边界和代价是否被正文新增事实推翻或补充。
3. 已发生事件的时间、地点、因果、选择、结果和存亡状态是否在章纲与控制台中准确回写；时间线事实截止是否等于最新定稿，当前锚点、连续时间段、期限、倒计时和不确定项是否与正文一致；地图中的区域、地点、连通关系、相对方向、通行限制和未确认空间是否与正文一致。
4. 正文已经新增或推进的角色、能力、关系、伏笔和阶段事实是否存在漏记；主角动态资产总账是否存在，当前概况是否与实际条目一致，事实截止是否与最新定稿一致。总账是否完整列出当前可调用能力或手段及其效果、限制、融合关系与事实依据，资源、关键物品、凭证和其他动态资产能否按获得、消耗、归还、转移、失效对账；写明“当前无需要追踪的动态资产”时，正文和章纲是否确实没有需要跨章节核对的资产。旧状态、旧字数、旧章节号、过期待办和临时区块是否仍未清理；角色状态文件是否混入已退出当前工作集的人物或累计逐章依据；阶段角色文件是否混入已结算人物或在最新结果中累计逐章历史，活跃条目与低频归档是否重复，归档索引是否指向实际条目。
5. 是否把猜测、梦境、谎言、角色误判、未确认身份或未来计划误记为客观事实；也要检查已经确认的事实是否仍被写成未知。
6. 同一事实在预期、设定、大纲和控制台中是否出现互相冲突的并行版本，未写章纲的入口状态是否仍能承接最新定稿正文。

#### 剧情方向检查

1. 当前阶段的完成标志是否全部达成，不能只看章节数量或单个高潮是否结束。
2. 最近十章的实际路线是否仍在推进当前阶段目标，还是已经形成持续偏移、替代路线或新的主要矛盾。
3. 核心读者承诺、人物目标、关键关系与硬约束是否仍与总纲一致。
4. 长期未推进的关键任务或伏笔是否已经影响阶段成立，需要调整近端规划或阶段表述。

#### 处理审计结果

- 控制台或已定稿章节章纲存在明确漏记、旧状态或与正文一一对应的记录错误时，直接按定稿正文修正，并在交付中列明。
- 预期、稳定设定、总纲、未写规划与正文冲突，或修正需要追溯改动定稿正文时，先列出“定稿事实 / 冲突文件与原记录 / 影响 / 建议处理”，等待用户确认；不能静默覆盖。
- 不能确认哪一份内容正确时，保留不确定性并报告问题，不自行补设定。
- 审计没有发现问题时，在收尾交付中明确写出“全项目一致性审计完成，未发现需要修订的出入”及核对范围。
- 审计发现阶段完成、持续偏移或近端安排已不适用时，另行输出“原计划 vs 实际走向 vs 后续影响”，等待用户确认后再修订规划。

短篇模式默认跳过十章节点审计，除非用户明确要求全面检查或调整尚未写的结局与方向。长篇在用户确认审计中需要修订的方案后，按下列分工执行：

- **待定稿同步**：逐条说明定稿事实与现有设定、总纲或未写规划的差异。用户确认同步后，按影响范围执行 `webnovel-setting-sync`、更新总纲或修订未来章纲；用户暂缓时保留待定稿同步项，不静默改动全局文档。

- **近端调整**：只改未写的十章章纲或未写章节的章纲，不改已定稿事实。
- **当前阶段调整**：阶段尚未完成时，只更新 `3-大纲/3.1_全书结构总纲.md` 的当前阶段或入口承诺，不补写未来阶段。
- **阶段切换**：当前阶段已经达到完成标志时，先按维护规则清理角色状态和阶段角色工作表，只保留明确带入下一阶段的动态状态与角色，再向用户说明实际收束结果并执行 `webnovel-outline`。由该技能归档已完成阶段摘要，并根据最新定稿事实共创下一个当前阶段；本技能不能自行推演并写入下一阶段。
- **设定事实调整**：先执行 `webnovel-setting-sync`，处理角色、规则、核心机制或世界设定的跨文件一致性，再回写受影响的大纲。
