# 正文审查规范

## 审查方只读

审查全程只读：不改写正文、设定、大纲或控制台，不代替作者决定剧情。发现的问题由写作会话处置，审查方不代为修改。

- 将正文技能目录记为 `SKILL_DIR`（即 `.agents/skills/webnovel-zhengwen/`），包含 `.agents/` 的项目根目录记为 `WORKSPACE_ROOT`。

## 验收对象

- 待审正文草稿 `4-正文/第X章_草稿_[标题].md`。
- 本章章纲条目：长篇为当前十章章纲文件中的对应条目，短篇为 `3-大纲/短篇章纲.md` 中的对应条目。

短篇模式下，`3-大纲/短篇方向大纲.md` 代替长篇总纲，字数参考 800-1500 字，第一章正文开头应含已确认的 `3-大纲/短篇导语.md`。

## 验收依据

读取待审正文与本章章纲条目，并读取下列控制台作为核对事实边界的依据：

- `控制台/时间线.md`：故事时间顺序、时段、跨日、期限与倒计时的事实边界。
- `控制台/地图.md`：区域、地点、连通关系、通行限制与未确认空间的当前事实边界。
- `控制台/主角能力与资源.md`：主角动态资产与可调用能力的当前事实边界。
- `控制台/角色状态.md`：角色当前处境、身体与精神状态，以及仍生效的禁令和余量。

待审草稿中的新增时间、地点、资产和状态一律视为本章待确认结果，不提前改写对应控制台。已有定稿但上述文件缺失或事实截止落后时，列为连续性风险，并以已读取定稿能证明的事实下限继续审查。第一章草稿尚未定稿时允许这些文件不存在，但必须指出第一次定稿时需要建立。审查方保持只读，不创建或修改控制台。

下列设定一并读取：

- 设定案与规则 → `2-设定/2.1_新书设定案.md`、`2-设定/2.1.1_武核设定.md`、`2-设定/2.1.2_境界设定.md`。
- 主要角色 → `2-设定/2.3_主要角色设定表.md`。
- 出现、复用或结算阶段角色 → `2-设定/2.3.1_阶段与功能角色记录.md`、`2-设定/角色归档/` 中的对应条目，不因角色是功能人物便跳过已经确认的能力、结果和写作边界。
- 核心机制、能力调用或规则边界 → `2-设定/2.2_金手指设定.md`，以已确认的规则、代价和限制核对，不因草稿内部自洽便接受临场新增的能力或规则。

项目根目录 `AGENTS.md` 每次审查都必须读取；规则类别不固定，以它的最新内容为准。

**下列材料不读取**：

- `控制台/伏笔追踪.md`、`控制台/进度.md`
- `2-设定/2.3.2_核心关系.md`
- `2-设定/2.4_文风.md`、`2-设定/参考作品/`
- `3-大纲/3.1_全书结构总纲.md`、`1-预期/`
- 其他章节的章纲条目与其他章节正文

材料缺失时只指出无法判断的项目，不把缺失材料当作问题本身。

## 检查维度

### 1. 产出格式

- 文件名是否为 `第X章_草稿_[标题].md`，标题是否与本章章纲一致。
- 正文是否从第一句正文开始，不含 `# 第X章`、章节名或其他标题行。
- 本章是否只保留一份草稿，没有并行草稿或旧版本混存。

### 2. 脚本校准复核

正文交付前必须执行三个强制脚本。审查方用**诊断模式**复核其结果，确认校准真实发生过。**一律不加 `--fix`**：写作会话已负责修复，审查方只读复核，不修改文件。

在 `WORKSPACE_ROOT` 下执行（`<SKILL_DIR>` 为 `.agents/skills/webnovel-zhengwen/`）：

```bash
python "<SKILL_DIR>/scripts/check_sentence_linebreaks.py" "<草稿路径>"
python "<SKILL_DIR>/scripts/fix_quotes.py" "<草稿路径>"
python "<SKILL_DIR>/scripts/count_chinese_words.py" <章号> "4-正文" --min-chars <参考下限> --max-chars <参考上限>
```

- 句号换行：脚本报告仍有句号后继续书写的行时，指出具体位置。
- 标点与引号：脚本报告未配对或待人工确认的引号时，指出具体位置。
- 字数：长篇参考 `2000` 至 `4000`，短篇 `800` 至 `1500`，用户指定范围优先。字数是参考区间，不作硬门槛；低于区间时先判断是否缺少必要推进、结果或场景，不因字数本身判为问题。
- **字数脚本按章号自动选文件，定稿优先，其余按文件名排序。同一章存在多个草稿时它可能选中不是待审的那份**：必须核对它输出的文件名与待审正文一致。不一致时该数字不可用，改用下方命令精确统计待审文件：

  ```bash
  python -c "import sys; sys.path.insert(0, '<SKILL_DIR>/scripts'); from pathlib import Path; import count_chinese_words as m; p=Path('<草稿路径>'); print(m.count_file(p), '字', p.name)"
  ```

### 3. 创作原料落实（重点专项）

**仅当本章章纲条目含「创作原料（定稿前临时保留）」节时才执行本节核对。** 没有该节时（未提供原料，或已定稿回写删除），本节直接跳过，**下列要求不必读**，报告里也不写这一节、不说明原因。

有该节时，逐条核对正文是否完整落实，**不得遗漏原料的任何内容**。

**逐句核对**：把创作原料拆成可核对的最小条目（每个事件、人物选择、结果、对白意图、具体动作、场景细节和表达重点各算一条），逐条到正文中找落点，确认每条都已落实。不允许只做整体印象式的比对。

- **位置可以变，意思不能变**：原料内容在正文中的先后顺序、出现位置、由谁叙述、放在哪个段落都可以调整；但事件、人物选择、结果、对白意图、具体动作、场景细节和表达重点必须一致，不得删减、弱化、替换或改变含义。
- **分拆与合并允许**：原料中一条内容可在正文拆成多处，或多条合并到一处，只要内容不丢、意思不变。
- **措辞自由度**：原料不决定最终句式与旁白措辞。正文用词、句式与原料不同不算遗漏；只有内容缺失或含义改变才算。
- **只列遗漏**：报告中只列遗漏条目，引用原料原文与正文对应位置（或指出正文中无对应内容）。遗漏属于必须修复的问题。
- 与章纲“剧情骨架”粒度不同不构成遗漏；原料与剧情骨架冲突时以原料为准。

### 4. 章纲落地

- 本章功能与目标、剧情骨架、读者回报或压力、伏笔与线索、结尾状态是否按章纲落地；章纲本章条目没写的项跳过，不当作缺失问题。
- **逐项核对后只报告未落地或存疑的条目**：全部落地时一句话说明该项已核对即可，不逐条列举正文位置来证明落地，也不报"共 N 项已落地"这类统计。只有未落地、部分落地或需要作者裁定的条目才写出正文位置与章纲原文。
- 正文与章纲不一致时，判断是正文更优、需回写章纲，还是正文偏离、需改正文；不自行裁定。
- 章纲中已记入“待定稿同步项”的差异不当作草稿错误，也不得据此把正文改回旧版本。

### 5. 事实边界与连续性

- **设定没写明时的处理**：正文写了设定文件里没有写明的规则、分类、参数或细节，而它与已有条目不冲突时，属于「设定待补全」，归入建议。**不要为此反复推演"哪一种解释才对"**——设定本身没写，就不存在可判定的答案。只有正文与已确认条目**冲突**，或正文凭空新增了能力、效果时，才判为问题。
- 时间是否能挂接到已有时间锚点；正文使用“次日”“数日后”或具体时辰时，是否有明确起点，不能精确时是否错误补算。
- **正文内部的时间量必须互相自洽**：正文给出的具体时刻、时长与相对时段必须能同时成立、推出同一个时间点。同一处时间由多个量共同确定而彼此矛盾时，按「正文自身矛盾」定级。
- **正文自身是否前后一致**：同一件事、同一场景、同一动作或同一人物在本章不同位置的表述能否同时成立，包括称谓、动作、指代、归属、时刻与时长。前后矛盾按「正文自身矛盾」定级，**不因"读者能自己读通"而放过**。
- 空间是否能挂接到已确认地点；转场、追逐、搜索、潜入或战斗是否落在已确认地点，或已明确标为本章新发现。
- 角色状态是否能支持正文的处境、身体与精神；时间、地点、在场人物、伤势、资源、物品、身份、关系和认知边界是否与前文一致。
- 主角使用的能力或手段是否确实在总账中可调用，效果与限制是否一致；资源、物品、凭证、权限和证据能否按获得、消耗、归还、转移与遗失对账，是否误用了已耗尽项目或遗漏旧库存。
- 结果是否能由人物行动、已知规则或前置线索推出。**只核对会改变局面的事件结果**——人物为何作出该选择、事件为何导致该结果、能力为何生效或失效；不逐处追问细节如何成立（动作怎么做到、道具怎么摸到、旁人为何没拦）。正文未交代的这类细节，只要不与已确认条目冲突、前后也不矛盾，不构成问题，也不必列为建议。
- 核心机制涉及时，是否符合 `2-设定/2.2_金手指设定.md` 中已确认的规则、代价、限制和风险，未临场新增能力或信息。判为问题的是正文出现设定未确认的新能力、新效果，或与已确认的代价、限制、风险相冲突。

### 6. 项目文本规则

- 对照项目根目录 `AGENTS.md` 逐条核对正文。
- 命中其中任一条的问题按实际影响定级。

### 7. 可读性

- 只审"读得懂读不懂"：正文是否存在信息缺失或表述导致读者**无法理解**当前在发生什么。不审文风，不作文风判定、不提文风类修改要求。
- **判为问题的只有一种**：读者读完该处后，无法确定发生了什么。
- **读者能自行理解、只是需要多想一步或多读一遍的，不判为问题，也不列为建议**。以下情形都属此类：位置关系需要从后文反推、时间量需要自己换算、身位需要从动作推断、某句话有两种读法但都能拼出合理时序。
- 察觉这类可读性摩擦时不展开权衡，直接放过：规范不要求把每一处"可能让读者多停一下"的地方都找出来。

## 处置分级

审查方必须把每一项发现明确归入下列两类之一，**不得含混**：

### 一、问题（必须修复）

对照验收依据可以直接判定的不符合项，审查方给出确定结论：

- **硬性不符合**：产出格式、脚本校准未执行、创作原料遗漏、章节信息与 `AGENTS.md` 冲突。
- **事实矛盾**：与时间线、地图、角色状态、能力资源总账或已确认设定冲突，或结果无法由人物行动、已知规则、前置线索推出。
- **正文自身矛盾**：同一件事、同一场景、同一动作或同一人物，在本章不同位置出现互相矛盾的表述，包括称谓、动作、指代、归属、时刻与时长。**判据是两处表述能否同时成立，不取决于读者是否容易读通**；能自行读通的一律不降级为可读性问题。
- **读者无法理解**：信息缺失或表述导致读者读完该处后无法确定发生了什么。
- **章纲未落地**：章纲本章条目写明的内容在正文中没有兑现。

每条问题必须写明：**位置**（文件、段落或原文引用）、**不符合哪条依据**、**为什么构成问题**、**修改方向**。只写"这里不好"不算问题。

### 二、建议（只提出，不要求修改）

审查方认为可以更好、但依据中没有强制要求，或不构成确定的错误的意见：

- **读者体验**：情绪力度、信息密度、场景详略、追读感上可以加强的地方。
- **可选项**：增补细节、调整顺序、替换说法等主观取舍。
- **设定待补全**：正文写了设定文件里没有写明、但也不违背已有设定的规则或细节。判据与处理见「检查维度」5 的首条，归入建议。

建议只要求写清**位置**与**想法**，并明确它是建议。**不得把建议写成问题，也不得用问题的方式要求修改**。

### 判定不确定时

无法在合理成本内定论时，如实写"未验证"并说明还缺什么材料，不硬下结论，也不凭"应当没问题"放行。**判不出属于问题还是建议时，一律归入建议**，在报告中说明存疑之处；不要在两节之间来回权衡。

## 效率约束

审查服务于交付，不做无边界挑刺：

1. **分批读完，边读边核**：待审正文、本章章纲条目、上述控制台与设定、`AGENTS.md` 全部读取，但**分批进行**——每读完一批就随即核对该批涉及的内容，再读下一批。不要把所有材料读完才开始核对，也不要边读边判断"还需要什么材料"（材料清单已在上文列全，按清单读即可）。
2. **逐条核完即完成**：核对以「检查维度」逐条走完为准。走完即视为审查完成，不必另行设想"可能存在的问题"再逐一排查——规范要求的是发现不符合项，不是穷举所有可能的不符合项。核对中有依据的疑点按「处置分级」处理；走完没有疑点就结束，直接出报告。
3. **一次取证**：在同一轮审查内，同一命令只跑一次；判断到可以落笔的程度即停止追查。
4. **可以无发现**：全部通过时直接输出通过结论，**不为了显得尽责而凑问题或把建议包装成问题**。
5. **只审本章**：审查对象是本章草稿。发现的问题若属于其他章节或全局资料，只记录并说明交由对应流程处理，不在本章强求。

审查方不读参照作品原文，不做文风比对。

## 执行流程

审查**一轮完成，不做复审**：报告交付后本次审查即结束，写作会话修正后不再发回审查方。修正是否引入新问题，由写作会话的脚本校准与自检卡负责。

1. 说明审查范围与已读材料。
2. 读取待审正文、本章章纲条目、控制台、设定与 `AGENTS.md`；材料按上文清单全部读取，**分批读、每批读完随即核对该批**，不在核对过程中回头补读遗漏的材料。判断必须落到具体文件、章节、段落或事实。
3. 以诊断模式运行三个脚本，复核校准是否真实发生；一律不加 `--fix`，不修改文件。
4. 逐句核对创作原料（如本章章纲含该节），只记录遗漏条目，取得逐条证据。
5. 按「检查维度」逐项走查，不得跳过维度；每个维度都要落到具体文件、章节、段落或事实。
6. 按「处置分级」把发现分入问题与建议两类，逐条写清位置、依据与理由。
7. 输出报告，交付给写作会话处置。报告交出后本次审查结束。

## 报告结构

```markdown
# 《[作品名或文件名]》正文审查报告

审查范围：[材料]
已读材料：[文件]

## 验收结论
[通过 / 有问题待修复 / 无法判定；未通过时列出阻断项]

## 已核对范围
[逐条列出本轮实际核对的维度与主要材料，说明哪些维度未核对及原因]

## 创作原料落实
[仅当本章章纲含「创作原料」节时保留本节：只列遗漏条目（原料原文摘要 → 正文中无对应内容）。
**章纲没有该节时整节省略，不写"不适用"，也不必说明原因。**]

## 问题（必须修复）
- **位置**：
  **依据**：
  **为什么是问题**：
  **修改方向**：
[无问题时写"未发现问题"]

## 建议（仅供参考，不要求修改）
- **位置**：
  **想法**：
[无建议时写"无"]

## 无法判定
[缺材料或超范围的项目；无则写"无"]
```

**各节无内容时按上面括号里的说明处理**：标"无"的照写，标"省略"的直接不写该节。不要在报告里解释为什么某一节是空的。

审查项没有证据时明确标注，不为凑报告补造问题。
